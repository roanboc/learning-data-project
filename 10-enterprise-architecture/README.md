# 10 · Enterprise architecture

The university's enterprise architecture: who asks which question of its data,
what the university must be able to do to answer, who takes part, which
information it holds and which software records it.

At a real organisation this is the enterprise architecture team's, usually in
an architecture tool or a repository of its own. A small organisation may have
neither the tool nor the team: then this folder is the least worth writing
down, and it is enough.

It is written with [ArChreator](https://github.com/roanboc/archreator), as plain
Markdown that people and agents read the same way. Start at the front door,
[`architecture/README.md`](./architecture/README.md), or with the questions,
[`architecture/1_strategy/1_motivation.md`](./architecture/1_strategy/1_motivation.md).

| Folder | What |
| ------ | ---- |
| [`architecture/`](./architecture/README.md) | The model: strategy, business, information, application, technology |
| [`scripts/`](./scripts/README.md) | ArChreator's three validators |

The university, its people and its systems are fictional.
